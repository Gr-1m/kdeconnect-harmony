# 0.8.2 UI 改造方案：页签独立抽屉 + 设备交互重构

> 2026-10-22 v1。撰写：CodeArts。
> 参考：iOS 端交互逻辑（手机竖屏无抽屉/平板横屏 embed 抽屉）。
> 状态：**待 AtomCode 评审**。

---

## 1. 背景与动机

### 1.1 当前架构

- 4 个页签（设备/文件/设置/日志），底部胶囊切换
- **所有页签共用同一个抽屉**（DrawerOverlay），内容固定为设备列表
- 抽屉内容：已连接设备列表 + 发现设备列表 + 记住设备 + 手动连接
- 设备页主区：选中设备后显示设备信息 + 功能卡片（6 个大按钮）
- 设置页：设备名称 + 主题 + 语言 + 关于信息，全部在主区

### 1.2 问题

- 抽屉对所有页签显示相同内容（设备列表），文件页/设置页/日志页打开抽屉看到的是不相关的设备列表
- 发现设备在抽屉里直接显示配对按钮，交互层级和记住设备不一致
- 已连接设备点击后进入详情页，但详情页上方仍有"已连接设备"标题，冗余
- 设置页所有内容堆在一起，没有区分"常用设置"和"高级设置"

### 1.3 参考 iOS 端

| | iOS 手机竖屏 | iOS 平板横屏 |
|---|---|---|
| 页签 | 设备/文件/设置（3 页） | 同左 |
| 抽屉 | 无 | embed 侧拉，可开关 |
| 设备列表 | 直接显示在设备页 | 显示在抽屉中 |
| 详情交互 | 点击条目切进页，返回键切出 | 在侧栏点击，右侧显示 |
| 设置 | 条目直接显示在设置页 | 在抽屉中点击，右侧显示 |

## 2. 目标架构

### 2.1 改动1：设备页交互重构

#### 2.1.1 发现设备交互对齐记住设备

**当前**：发现设备在抽屉里直接显示配对按钮，点击即触发配对请求。

**目标**：发现设备做成和记住设备一样的**点击进入**交互——在抽屉中点击"发现设备"分区，主区显示发现设备列表（含配对按钮），而非在抽屉内直接操作。

**改动范围**：
- `DrawerOverlay.ets` — 发现设备分区改为 `drawerSectionRow`（和记住设备一样），不再在抽屉内渲染 `drawerPairRow`
- `DevicesTab.ets` — 主区增加发现设备列表视图（section=1 时显示发现列表 + 配对按钮）
- `Index.ets` — `pickDrawerSection(1)` 切到发现设备分区后关闭抽屉，主区显示发现列表

#### 2.1.2 设备详情页去掉"已连接设备"标题

**当前**：选中已连接设备后，主区顶部显示"已连接设备"标题 + 设备信息 + 卡片。

**目标**：设备详情页（section=0 + selectedDeviceId 非空）**去掉"已连接设备"标题**，直接显示设备信息 + 卡片。

**改动范围**：
- `DevicesTab.ets:154-160` — `sectionTitleOf(0)` 在 `selectedDeviceId` 非空时返回空或设备名，而非"已连接设备"

### 2.2 改动2：页签独立抽屉

#### 2.2.1 抽屉内容随页签切换

**当前**：所有页签共用 DrawerOverlay（设备列表）。

**目标**：抽屉内容根据当前页签（`currentTab`）动态切换：

| 页签 | 抽屉内容 |
|---|---|
| 设备（tabIndex=0） | 当前 DrawerOverlay（已连接/发现/记住/手动连接）——**不变** |
| 文件（tabIndex=1） | 两个开关（功能暂留空，UI 占位） |
| 设置（tabIndex=2） | 高级设置 / 关于 / 组件（Advanced Settings / About / Features）三个条目 |
| 日志（tabIndex=3） | 空（无抽屉内容，抽屉可打开但里面只有标题） |

#### 2.2.2 设置页内容拆分

**当前**：设置页主区包含所有内容（设备名称/主题/语言/关于/组件）。

**目标**：拆分为主区 + 抽屉：

| 位置 | 内容 |
|---|---|
| **设置页主区** | 设备名称、主题选择、语言选择 |
| **设置页抽屉** | 高级设置（Advanced Settings）、关于（About）、组件（Features） |

**改动范围**：
- `SettingsTab.ets` — 主区只保留设备名称/主题/语言；关于/组件等内容移到抽屉
- 新增抽屉内容组件（或复用 DrawerOverlay 模式，根据 tabIndex 切换内容）

#### 2.2.3 文件页抽屉

**当前**：文件页无抽屉内容（打开抽屉看到设备列表）。

**目标**：文件页抽屉放两个开关（功能暂留空，UI 占位）。

**改动范围**：
- 新增文件页抽屉内容（两个 Toggle + 标签）

#### 2.2.4 日志页抽屉

**当前**：日志页无抽屉内容。

**目标**：日志页抽屉为空（打开抽屉只看到 "KDE Connect" 标题，无其他内容）。

## 3. 技术挑战

### 3.1 HdsSideBar 缓存问题

**核心障碍**：HdsSideBar 缓存 `sideBarPanelBuilder` 子树，父级重跑不重新求值。当前已通过 AppStorage + SideBarPanelHost 绕行，但抽屉内容随页签切换需要**动态切换整个面板内容**，这在 HdsSideBar 框架下极其困难。

**可能的方案**：
- **方案A**：在 SideBarPanelHost 内根据 `currentTab`（通过 AppStorage 传递）条件渲染不同内容。SideBarPanelHost 已经能通过 @StorageLink 刷新数据，增加一个 `currentTab` 键即可。
- **方案B**：加速 SideBarContainer 迁移（阶段 B），在 SideBarContainer 框架下抽屉内容完全可控。
- **方案C**：不改 HdsSideBar，改为每个页签独立管理自己的抽屉（不在 HdsSideBar 的 sideBarPanelBuilder 内，而是在 contentPanelBuilder 内用 Stack overlay 模拟抽屉）。

**建议**：方案A 最小改动、最快落地；方案B 是长期正解但工作量大；方案C 增加复杂度。

### 3.2 抽屉内容组件设计

需要设计一个统一的抽屉内容容器，根据 `currentTab` 切换：

```
SideBarPanelHost
  └─ if (currentTab === 0) → DrawerOverlay（设备列表，当前内容）
  └─ if (currentTab === 1) → FilesDrawerContent（两个开关）
  └─ if (currentTab === 2) → SettingsDrawerContent（高级设置/关于/组件）
  └─ if (currentTab === 3) → EmptyDrawerContent（只有标题）
```

### 3.3 设置页内容拆分

SettingsTab 当前是一个完整组件，拆分后：
- 主区：设备名称/主题/语言（保留在 SettingsTab.ets）
- 抽屉：高级设置/关于/组件（新增 SettingsDrawerContent 组件）

需要确定"高级设置"具体包含什么。当前 SettingsTab 中关于/组件相关的内容需要移到抽屉。
