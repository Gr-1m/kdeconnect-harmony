# 方案 — 平板双面板整治（CodeArts 提案 v0.1）

- 日期：2026-11-08
- 作者：CodeArts
- 背景：同 Omp-ArkTS `PROPOSAL_TABLET_DUAL_PANEL_20261110.md`（MSG179 §3）
- 约束：下拉刷新必须保留并移到「发现设备」位置；未拍板前不动结构

## 1. 对 Omp 方案的评审

Omp 方案 A（删除 rail，只留主区 + 页面侧栏）方向正确，与 S7 同向。以下评审要点：

| 点 | 评价 |
|---|---|
| 删除 sideBySide 分支 | ✅ 消除信息架构冗余的根本手段 |
| 分区选择全部由 HdsSideBar 承担 | ✅ DrawerContentModel 已有 onPickSection/onOpenDevice |
| 下拉刷新落点 = 侧栏发现设备分组 + 主区分区 2 | ⚠️ 侧栏收起态需按钮兜底，但按钮交互不如手势自然 |
| 改动量 ~30 行 + 1 prop | ✅ 低成本 |

Omp 方案 B（保留 rail 只去重）不推荐——两层导航未根治，rail 仍占 30% 宽度，S7 还需再删一次。

## 2. CodeArts 方案 C：平板 = 手机布局 + 侧栏增强

**核心思路**：平板不再有独立的 sideBySide 布局分支，**与手机共用同一套 DevicesTab 布局**（单列 Scroll + 分区内容），设备/分区选择全部由页面级 HdsSideBar 承担。与 Omp 方案 A 的区别在于主区形态。

### 结构

```
HdsSideBar（平板 40%，收起为迷你栏）
  └─ DrawerContentModel
       ├─ 已连接设备列表（onOpenDevice → 主区切换设备详情）
       ├─ 记住设备分区行（onPickSection → 主区切换分区）
       ├─ 发现设备分区行（onPickSection → 主区切换分区）
       │    └─ 刷新按钮（点击 → onRefreshDiscovery()）
       └─ 手动连接

主区（100% 宽，与手机同一 DevicesTab 组件）
  └─ Scroll(mainScroller)
       └─ 分区内容（由 currentSection 驱动）
            ├─ section 0：已连接设备详情
            ├─ section 1：记住设备列表
            └─ section 2：发现设备列表 + Refresh（下拉刷新，手机/平板一致）
```

### 与 Omp 方案 A 的差异

| 维度 | Omp A | CodeArts C |
|---|---|---|
| 主区布局 | 保留 sideBySide 分支的 Scroll + 分区标题，只删 rail | **完全删除 sideBySide 分支**，平板 = 手机布局 |
| 分区标题 | 主区保留分区标题行 | 主区不保留分区标题（侧栏已标明当前分区，主区只展示内容） |
| 代码改动 | DevicesTab 删 rail ~30 行 + 1 prop | DevicesTab 删整个 sideBySide 分支 ~50 行，简化为单列 |
| 下拉刷新 | 侧栏发现设备分组 + 主区分区 2 | **仅主区分区 2**（与手机完全一致，无需侧栏加 Refresh） |
| 侧栏收起态 | 需按钮兜底（侧栏内加刷新按钮） | 不需要（刷新在主区，与侧栏状态无关） |

### 优点

1. **零侧栏收起态问题**：下拉刷新始终在主区，不受侧栏开合影响
2. **平板/手机代码统一**：DevicesTab 不再有 sideBySide 分支，减少维护面
3. **主区全宽**：100% 宽度利用率
4. **与 S7 完全同向**：单一内容面，无 rail/双面板需要重排

### 代价

1. 侧栏收起为迷你栏时，分区切换需先展开侧栏（但 HdsSideBar 迷你栏通常仍显示图标按钮，可点击展开）
2. 主区无分区标题行——用户在侧栏选择分区后，主区直接展示内容，当前分区由侧栏高亮指示（DrawerContentModel 已有 section 高亮机制）
3. 改动量略大于 A（删整个分支 vs 删 rail）

## 3. 方案对比（三方案）

| 维度 | Omp A（删 rail 留主区分支） | Omp B（保留 rail 去重） | CodeArts C（删 sideBySide 统一布局） |
|---|---|---|---|
| 信息架构 | 单层 | 两层 | 单层 |
| 主区宽度 | 100% | 70% | 100% |
| 下拉刷新 | 侧栏 + 主区 | rail 顶部 | **仅主区**（最简） |
| 侧栏收起态 | 需按钮兜底 | 低风险 | **无此问题** |
| 平板/手机代码 | 仍有分支差异 | 仍有分支 | **完全统一** |
| 改动量 | ~30 行 + 1 prop | ~15 行 | ~50 行（删整个分支） |
| 对 S7 | 合并改造面 | 需再删 rail | **零改造面**（已是单列） |

## 4. 推荐

**方案 C**。理由：
1. 一次性消除 sideBySide 分支，平板/手机共用同一布局，后续维护面最小
2. 下拉刷新落点与手机完全一致（主区分区 2），无需在侧栏加任何兜底机制
3. S7 零改造面——C 已是单列单滚动面形态
4. 侧栏收起态不引入新问题（刷新在主区，与侧栏无关）

若用户更倾向最小改动量，退 **方案 A**（保留主区分支结构，只删 rail）。

## 5. 待裁决

3. 方案 C 的 sideBySide 分支删除是否影响平板横屏的其他逻辑（需 Omp-ArkTS 确认无其他依赖）
